# Ship Tracker — живой AIS для портов Дуная и северо-западного Причерноморья

Наблюдение за судами по реальным данным AIS: карта-радар, таблицы судов и стоянок,
прогноз маршрута на 5 дней, алерты и телеграм-бот с карточками судов.

Порты наблюдения: Рени, Измаил, Вилково, Черноморск, Одесса, Южный.

---

## Как запускать

### 1. Из папки (двойной клик)

Откройте папку `ship_tracker` и запустите нужный файл:

| Файл | Что делает |
|---|---|
| `run.bat` | приложение с окном (карта, суда, стоянки, настройки) |
| `bot.bat` | телеграм-бот |
| `setup.bat` | только подготовить окружение, ничего не запускать |

Первый запуск на новом компьютере занимает 1–3 минуты: скрипт находит Python,
создаёт папку `.venv` и ставит зависимости. Дальше запуск мгновенный.
Приложение и бот можно держать открытыми одновременно: AIS принимает только
один процесс, второй читает ту же базу (`data/feed.lock`).

Требования: Windows, Python 3.9+ (лучше 3.11–3.13) с сайта python.org,
при установке отметьте **Add python.exe to PATH**. Интернет нужен при первом
запуске (скачать зависимости) и, конечно, для самих данных AIS.

### 2. Из командной строки (cmd)

Откройте «Командная строка» и перейдите в папку проекта:

    cd /d "C:\путь\к\проекту\ship_tracker"

Дальше:

    run.bat                       приложение с окном
    bot.bat                       телеграм-бот
    setup.bat                     только окружение

    run.bat --headless --minutes 60    приложение без окна на 60 минут
    run.bat --headless                 без окна, пока не закроете (Ctrl+C)

Приложение можно запустить и напрямую, минуя bat-файл (аргументы те же):

    .venv\Scripts\python.exe -X utf8 ship_tracker.py
    .venv\Scripts\python.exe -X utf8 ship_tracker.py --headless --minutes 60
    .venv\Scripts\python.exe -X utf8 telegram_bot.py

В PowerShell те же команды пишутся с `.\`:

    .\run.bat
    .\bot.bat
    .venv\Scripts\python.exe -X utf8 ship_tracker.py

На Linux/macOS:

    ./run.sh

### 3. Что открыть после запуска

Окно приложения: карта и список судов, вкладки «Все суда», «Стоянки», «Цели»,
«Подключение» и «Настройки». Ключи API и токен бота вводятся на вкладке
«Подключение» и сохраняются в `data/config.json` (в репозиторий не попадают).
Структура настроек — `data/config.example.json`.

## Если проблемы с окружением

Папка `.venv` привязана к конкретному компьютеру и к пути, поэтому переносить
её нельзя. Копируйте проект **без** `.venv` и `.venv_old` — окружение соберётся
заново.

**«Окружение .venv не подходит этому компьютеру — собираю заново»**
Это нормальное сообщение: скрипт сам переименовал старое окружение в
`.venv_old` и ставит новое. Дождитесь окончания. Папку `.venv_old` после
успешного запуска можно удалить — она больше не нужна и занимает ~100 МБ.

**«Не найден Python 3»**
Установите Python с https://www.python.org/downloads/windows/, при установке
отметьте **Add python.exe to PATH**, закройте и откройте командную строку,
проверьте:

    py -3 --version
    python --version

**«Версия Python слишком старая»**
Нужен 3.9 или новее, лучше 3.11–3.13. Установите новый Python и запустите
`run.bat` снова. Старый можно не удалять.

**«Не удалось установить зависимости из requirements.txt»**
Проверьте интернет, VPN/прокси и антивирус. Затем повторите:

    setup.bat

Если не помогло — установите вручную и посмотрите текст ошибки:

    .venv\Scripts\python.exe -m pip install -r requirements.txt

**«Не удалось создать .venv»**
Чаще всего мешает OneDrive (папка синхронизируется) или антивирус. Приостановите
синхронизацию OneDrive на время установки, затем повторите `setup.bat`.
Полный сброс окружения:

    rmdir /s /q .venv
    rmdir /s /q .venv_old
    setup.bat

**Проверить, что окружение собрано правильно**

    .venv\Scripts\python.exe -c "import tkinter, requests, websockets, PIL, aiogram"

Если команда завершилась без ошибок — всё на месте. Если ругается на `tkinter`,
переустановите Python с python.org (в стандартном установщике tcl/tk включён).

**Кракозябры вместо русского текста**
Bat-файлы сами переключают кодировку. Если запускаете Python напрямую, добавьте
флаг `-X utf8` (он уже есть в примерах выше).

**«Приложение мигнуло и закрылось»**
Причина пишется в `data/errors.log`. Откройте файл и посмотрите последнюю
запись. Также помогает запуск из `cmd` — текст ошибки останется в консоли.

**Бот не отвечает / «второй экземпляр»**
Бот держит `data/bot.lock`, чтобы две копии не отвечали в один чат. Закройте
лишние окна бота. Если бот упал и файл остался, удалите `data/bot.lock`
(только когда ни один бот не запущен) и запустите `bot.bat` снова.

**Нет данных на карте**
Проверьте вкладку «Подключение»: у каждого канала свой статус и кнопка
«Проверить». Ключ AISStream — бесплатный, с aisstream.io. Снимок района и
Open Waters работают без ключа. Если статусы «на связи», а судов нет — значит
у выбранных портов сейчас нет покрытия AIS; список наполняется по мере
появления судов.

## Что внутри

    ship_tracker/            приложение и бот
      ship_tracker.py        окно: карта, суда, стоянки, цели, настройки
      core.py                приём AIS, геозоны, фильтр, алерты
      ais_feed.py            AISStream, Open Waters, снимок района, треки
      services_feed.py       внешние API по ключу (VesselFinder, MyShipTracking, Digitraffic)
      forecast.py            прогноз маршрута на 5 дней
      telegram_bot.py        бот: порт → суда в этот порт, карточки, автообновление
      store.py               SQLite: суда, позиции, визиты
      env.bat                проверка и сборка .venv (вызывают run/bot/setup)
      data/                  настройки и база (не коммитятся)
    open_ship_tracker.py     запуск приложения из корня
    ship_tracker/README.md   подробное описание, каналы данных и лимиты

## Каналы данных

* **AISStream** — основной живой поток (нужен бесплатный ключ).
* **Open Waters AIS** — второй живой поток и снимок района без ключа.
* **MyShipTracking** — бесплатный триал: расширенные данные по нашим судам
  с дневным лимитом кредитов.
* **VesselFinder / MarineTraffic / Digitraffic** — по наличию ключа
  (у VesselFinder LiveData только по подписке).

AIS принимает только один процесс: приложение и бот делят поток через
`data/feed.lock`, второй читает общую базу.
